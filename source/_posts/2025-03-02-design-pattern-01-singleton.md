# 单例模式（Singleton）

## 一、模式概述

**单例模式**保证一个类在全局只有一个实例，并提供一个统一的访问点。

**解决的问题**：某些对象（配置、连接池、线程池、日志等）只需要一份，多实例会造成资源浪费或状态不一致。

**定义**：确保某个类只有一个实例，并自行实例化并向整个系统提供该实例。

---

## 二、结构与实现方式

**角色**：单例类（自己负责创建唯一实例，并提供静态获取方法）。

**常见实现**：

| 方式 | 优点 | 缺点 |
|------|------|------|
| 饿汉式（静态常量/静态块） | 线程安全、实现简单 | 类加载即创建，可能用不到也占内存 |
| 懒汉式（synchronized 方法） | 用时再创建 | 每次获取都加锁，性能差 |
| 双重检查锁（DCL） | 懒加载 + 较少加锁 | 需 volatile，实现稍复杂 |
| 静态内部类 | 懒加载、线程安全、代码简洁 | 仅适用于无参构造 |
| 枚举 | 防反射/反序列化破坏、最简洁 | 无法懒加载 |

**示例（静态内部类）**：

```java
public class Singleton {
    private Singleton() {}
    private static class Holder {
        private static final Singleton INSTANCE = new Singleton();
    }
    public static Singleton getInstance() {
        return Holder.INSTANCE;
    }
}
```

---

## 三、在 Spring 中的运用

- **Bean 默认作用域即为单例**：`@Scope("singleton")`（默认），同一 IoC 容器内同一 Bean 定义只对应一个实例。
- **ApplicationContext 本身**：通常整个应用只有一个主 Context，可视为单例的“容器”。
- **常见单例 Bean**：数据源、事务管理器、模板类（如 JdbcTemplate）、工具类等，由容器保证单例而非手写 getInstance()。

**注意**：Spring 是“容器内单例”，多容器可有多个实例；且 Bean 可由配置改为 prototype 等其它作用域。

---

## 四、适用业务场景

- **配置、全局设置**：如系统配置类、 feature 开关，全应用一份即可。
- **连接池、线程池**：如数据源、Executor，复用同一池，避免重复创建。
- **无状态工具类**：如日期/加密工具，无实例状态，单例减少对象数量。
- **缓存、注册表**：如本地缓存、服务注册表，需要全局唯一访问点。

**不适用**：有实例状态且不同调用方需要隔离的对象（应用 prototype 或多例）、需要延迟加载且对内存敏感又很少用的组件（可结合懒加载作用域）。

---

## 五、小结

单例模式通过“唯一实例 + 统一访问点”控制全局资源与无状态对象；Spring 中通过 Bean 的 **singleton 作用域** 实现，无需手写单例逻辑。业务上多用于配置、池、工具、缓存等“全应用一份”的场景。
