LangChain4j Splitter Package — Document Splitting Source Code Overview

Overview

LangChain4j provides document splitting under the package dev.langchain4j.data.document.splitter: the DocumentSplitter interface splits a Document into multiple TextSegments, with support for different granularities such as character, line, paragraph, sentence, word, and regex.

  • Package docs: dev.langchain4j.data.document.splitter

Core Interface

DocumentSplitter

  • Input: Document
  • Output: List<TextSegment>, each segment bounded by maxSegmentSize

Built-in Splitters (LangChain4j)

Class Separator / behavior Description
DocumentByParagraphSplitter "\n\n" By paragraph
DocumentByLineSplitter "\n" By line
DocumentBySentenceSplitter Sentence boundary By sentence
DocumentByWordSplitter " " By word
DocumentByCharacterSplitter Character By character
DocumentByRegexSplitter Regex By regex
HierarchicalDocumentSplitter - Base for hierarchical splitting

Source Overview: HierarchicalDocumentSplitter and SegmentBuilder

1. Overall flow (HierarchicalDocumentSplitter.split)

The core of hierarchical splitting is HierarchicalDocumentSplitter.split(Document):

  1. Use the subclass’s split(text) to get parts at the current granularity (e.g. paragraph, line, word).
  2. Use SegmentBuilder to combine multiple parts into one segment under maxSegmentSize; when it no longer fits, flush the current segment, then take a tail overlap of size maxOverlapSize as the start of the next segment.
  3. If a single part exceeds maxSegmentSize, hand it to subSplitter for further splitting (e.g. long paragraph → split by sentence); sub-split results are reattached to the original Document’s metadata by index.

Size can be measured by character count or token count: via TokenCountEstimator and estimateSize(text) injected into SegmentBuilder’s length calculation.

2. SegmentBuilder’s role and structure

SegmentBuilder (dev.langchain4j.data.document.splitter.SegmentBuilder) is a package-level utility (@Internal), with no private inner classes. It only: concatenates text segments with a given separator without exceeding maxSegmentSize, and supports building overlap by prepending text in reverse order with prepend.

3. Overlap and subSplitter

  • Overlap: After flushing a segment, overlapFrom(segmentText) takes up to maxOverlapSize from that segment by sentence in reverse order as the start of the next segment, so adjacent segments overlap and semantics are not cut at boundaries.
  • subSplitter: When a single part is too long, a sub-splitter (e.g. DocumentBySentenceSplitter) is used; subclasses specify the default via defaultSubSplitter() (e.g. paragraph → sentence → word → character chain).

Recommended usage: DocumentSplitters.recursive()

LangChain4j recommends recursive splitting for general text: try levels in order—paragraph → line → sentence → word → character—until maxSegmentSize is satisfied.

Supports controlling size by character count or token count.

Python RecursiveCharacterTextSplitter Source Code Walkthrough

Overview

RecursiveCharacterTextSplitter is the recommended general-purpose text splitter in LangChain Python. It recursively splits text by separator priority, trying to keep paragraphs, sentences, and words intact until each chunk satisfies the chunk_size limit.

  • Official API: RecursiveCharacterTextSplitter

Default Separator Order

Separators are tried in order of priority until the resulting chunks do not exceed chunk_size:

Priority Separator Meaning
1 "\n\n" Paragraph
2 "\n" Line
3 " " Space (word)
4 "" Character (fallback)

That is: split by paragraph first; if still too long, split by line, then by space, and only then by character.

Source Code Walkthrough

LangChain Python’s RecursiveCharacterTextSplitter extends TextSplitter. The core logic lives in recursive splitting by separator and merging with overlap.

1. Recursive splitting: _split_text

Split the text by the “current separator” into segments; if a segment still exceeds chunk_size, recursively split that segment with the “next finer separator”.

Summary:

  • Use _split_on_separator(text, sep) to get splits at the current level.
  • Segments with length ≤ chunk_size go into good_splits; when a batch is ready, merge with _merge_splits and yield.
  • For segments with length > chunk_size: if rest_separators is non-empty, recurse with _split_text(s, rest_separators); otherwise merge at the current level or fall back to character-level.

2. Merging and overlap: _merge_splits

Merge a batch of small segments into chunks of about chunk_size, with chunk_overlap between adjacent chunks.

Summary:

  • Iterate over splits and accumulate length; when exceeding chunk_size, emit the current chunk, then drop segments from the front according to chunk_overlap to achieve overlap.
  • _join_docs joins the list into the final string using separator.

Algorithm summary

  1. Recursion: Split with the current separator; if any segment is still longer than chunk_size, recursively split that segment with the next separator.
  2. Overlap: Keep chunk_overlap characters (or tokens) between adjacent chunks to avoid breaking semantics at boundaries.
  3. Length: By default uses len() (character count); length_function can be set to token count (e.g. tiktoken).
